# X Flip 实机联调记录

日期：2026-10-07

## 设备与游戏

设备为 vivo V2256A，Android 14（API 34），实际外屏 `displayId=1`，682 × 422，300 dpi，60 Hz

“超级小副屏”为 `cn.pashiguoke.subscreen`，1.5 正式版。通过该工具外屏桌面上滑进入完整应用列表，点击“AC 外屏仪表”，系统记录确认启动来源为 `cn.pashiguoke.subscreen`，仪表窗口位于 display 1

游戏为经典版 Assetto Corsa，赛道 Monza，车辆 `ks_maserati_alfieri`。用户实际进入驾驶、加速换挡并完成一圈

## 四项功能

- 挡位与转速：30 秒真实驾驶采集约 1801 帧，原始挡位出现 1、3、4、5、6，转速 3634–7506 RPM，车速达到 225.47 km/h。Android 解码验证 AC 原始挡位转换
- 单圈计时：完成圈数变为 1，游戏共享内存上一圈与最佳圈均为 368026 ms。最终外屏显示 `6:08.026`，本圈 `0:11.981`，暂停状态明确标注
- 车况：实机显示真实燃油 30.0 L、四轮胎芯温度和胎压，维修区提示已在实际游戏中触发。低燃油、驶离赛道等提醒通过明确标注的演示数据验证，车损、旗号优先级另有解码与告警逻辑检查
- 地图：本地 Monza 的 AI 路线解析为 128 点，实机原生绘制，驾驶采集确认 X/Z 本车坐标实际变化，截图可见本车位置

四个底部标签通过真实外屏触控切换，页面无文字裁切，设置弹窗也能在外屏显示

## 刷新与延时

Windows 发送端本地捕获连续 30 秒约 60.03 Hz，未发现序号跳帧。其他独立采集为 59.98–59.99 Hz

手机外屏诊断在稳定前台阶段约 59.7–59.8 次绘制/秒。界面截图中的局域网 RTT 有 5、6、7、10、15、16 ms 等样本。手机记录的收到最新遥测至进入绘制阶段也有 3、5、20 ms 等样本

本地探测脚本中的约 1.5–1.9 ms RTT 是电脑回环测量，不能当成手机 Wi-Fi 延时

这些统计没有测量游戏产生数据到屏幕实际发光的完整单向延时，没有进行高速摄像或两个设备之间的时钟同步。界面因此明确标为 RTT

一次最终版本渲染统计中，3231 帧有 8 帧未满足框架截止时间（0.25%），P95 框架帧耗时为 14 ms。该采样包含界面设置操作，不等于完整游戏到外屏显示延时

## 恢复与一致性

在最终 APK 中主动停止本次桥接程序，外屏隐藏旧驾驶数值并显示“遥测已中断”，也不保留旧 RTT。恢复桥接后约 2.5 秒内观察到自动恢复路线和数据，不需要重新打开应用

探测客户端退出后的发送端退出问题已修复，随后多次探测结束、外屏切页及应用暂停恢复后，桥接仍正常运行
